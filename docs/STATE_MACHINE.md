# Состояния заявки

Диаграмма состояний находится в `DIAGRAMS.md` (раздел 3). Здесь — таблица допустимых переходов и подписи, которые видит клиент.

## Статусы

| Код | Подпись в банке | Подпись клиенту (версия 2) | Смысл |
|---|---|---|---|
| `DRAFT` | Черновик | Черновик | клиент заполняет заявку |
| `SUBMITTED` | Подана | Подана | заявка принята банком, идёт проверка полноты |
| `NEED_INFO` | Нужны данные | Нужны данные | банку не хватает сведений, клиент должен дополнить |
| `SCORING` | Скоринг | Проверка | банк оценивает риск и принимает решение |
| `MANUAL_REVIEW` | Ручная проверка | На рассмотрении | заявку рассматривает сотрудник банка |
| `OFFER_MADE` | Предложение условий | Есть предложение | банк предложил условия, ждёт ответа клиента |
| `SIGNING` | Подписание | Подписание | клиент принял условия и подписывает договор |
| `ISSUED` | Выдан | Кредит выдан | кредит выдан (в симуляции) |
| `DECLINED` | Отказ | Отказ | банк отказал |
| `CLOSED` | Закрыта | Закрыта | клиент отклонил предложение |

Конечные состояния: `ISSUED`, `DECLINED`, `CLOSED`.

## Допустимые переходы

Любой переход, которого нет в таблице, запрещён и возвращает `409`.

| Из | В | Кто и при каком условии |
|---|---|---|
| — | `DRAFT` | клиент создал черновик |
| `DRAFT` | `SUBMITTED` | клиент отправил, данные валидны, даны согласия |
| `SUBMITTED` | `NEED_INFO` | система: проверка полноты не пройдена |
| `NEED_INFO` | `SUBMITTED` | клиент дополнил данные или документы |
| `SUBMITTED` | `SCORING` | система: данные приняты |
| `SCORING` | `OFFER_MADE` | система: авто-одобрение или авто-встречное предложение |
| `SCORING` | `DECLINED` | система: жёсткий стоп или грейд `D` |
| `SCORING` | `MANUAL_REVIEW` | система: нужен андеррайтер, создаётся задача |
| `MANUAL_REVIEW` | `MANUAL_REVIEW` | андеррайтер отложил задачу |
| `MANUAL_REVIEW` | `NEED_INFO` | андеррайтер запросил данные у клиента |
| `MANUAL_REVIEW` | `OFFER_MADE` | андеррайтер одобрил, в том числе с изменёнными условиями |
| `MANUAL_REVIEW` | `DECLINED` | андеррайтер отказал, причина обязательна |
| `OFFER_MADE` | `SIGNING` | клиент принял предложение |
| `OFFER_MADE` | `CLOSED` | клиент отклонил предложение |
| `SIGNING` | `ISSUED` | клиент подписал договор кнопкой, выполнена симуляция выдачи |

## Правила

- Запрос данных, встречное предложение и пересчёт скоринга происходят **внутри той же заявки**.
- Повторная подача после отказа создаёт **новую заявку**; её можно предзаполнить данными отказанной.
- Каждый переход выполняется в одной транзакции с записью в историю (кто, откуда, куда, комментарий).
- Конкурентные изменения защищены оптимистической блокировкой (версия заявки).
- После ответа клиента на запрос данных задача возвращается **тому же андеррайтеру** с приоритетом 1; автоматическое решение для такой заявки не применяется.

## Реализация

Таблица переходов задана в `ApplicationStatus` (backend), единственная точка смены статуса — `StatusTransitionService`: проверка перехода, сохранение с проверкой версии, запись в `status_history`, `audit_event` и ленту клиента в одной транзакции. Допустимые и запрещённые переходы покрыты тестом `ApplicationStatusTest`.
