# Метрики продукта

Метрики связывают цели кейса и выводы исследования ([`research/RESEARCH_TO_PRODUCT.md`](research/RESEARCH_TO_PRODUCT.md)) с данными, которые прототип уже собирает. Целевые значения указаны как гипотезы для пилота: на синтетических данных их проверить нельзя.

## Главная метрика

**Доля заявок, дошедших до выдачи, и время от отправки заявки до денег на счёте.** Обе части отражают задачу кейса: провести предпринимателя от потребности до результата и дать банку управлять этим процессом. Рост доли выдач за счёт ослабления оценки риска не считается улучшением, поэтому главная метрика читается вместе с метриками качества решений.

## Дерево метрик

| Уровень | Метрика | Как считается | Источник в прототипе | Гипотеза для пилота |
|---|---|---|---|---|
| Привлечение | конверсия подбора в черновик | черновики / подборы продуктов | журнал `audit_event`, таблица `loan_application` | рост после запуска помощника |
| Оформление | доля отправленных черновиков | отправленные заявки / черновики | `loan_application.status`, `status_history` | выше 70% |
| Оформление | время от черновика до отправки | медиана `submitted_at − created_at` | `loan_application` | меньше 10 минут |
| Оформление | доля заявок, вернувшихся в «Нужны данные» | заявки с переходом в `NEED_INFO` / отправленные | `status_history` | снижение после конкретных запросов документов |
| Рассмотрение | время до решения | медиана времени от `SUBMITTED` до `OFFER_MADE` или `DECLINED` | `status_history`; таймер `credit_pipeline_duration` | автоматические решения за минуту, ручные в пределах срока обработки |
| Рассмотрение | доля автоматических решений | автоматические исходы / все решения | счётчик `credit_decisions{outcome}` | 60–70% простых заявок без участия человека |
| Рассмотрение | доля задач, решённых в срок | задачи, закрытые до `sla_due_at` / все задачи | таблица `bank_task` | выше 90% |
| Решение | доля принятых предложений | переходы `OFFER_MADE → SIGNING` / все предложения | `status_history` | для встречных предложений отдельно |
| Выдача | доля выдач и сумма выдач | счётчик и сумма выданных кредитов | `credit_loans_issued`, `credit_loans_issued_amount` | главная метрика |
| Качество | доля решений андеррайтера с запросом данных | `REQUEST_INFO` / все решения андеррайтера | счётчик `credit_bank_decisions{result}` | снижение по мере улучшения запросов |
| Качество | доля просрочек по выданным кредитам | в промышленной версии по данным обслуживания | нет в прототипе | не выше портфеля сопоставимых продуктов |
| Помощник | доля диалогов, закончившихся действием | события `ASSISTANT_ACTION` / события `ASSISTANT_OPENED` | `audit_event` | выше 30% |
| Помощник | доля принятых автоматических предложений помощи | `ASSISTANT_OFFER_ACCEPTED` / `ASSISTANT_OFFER_SHOWN` | `audit_event` | выше 20%, иначе пересмотреть пороги |
| Надёжность | ошибки входа, отказы внешних источников | счётчик `credit_auth_login_failures`, заявки с причиной `SOURCE_UNAVAILABLE` | Prometheus, `credit_decisions{reason}` | для оповещений, а не для целей |

## Как посмотреть в прототипе

Технические и бизнес-счётчики Prometheus отдаются на служебном порту backend внутри сети стенда:

```bash
docker compose exec backend wget -qO- http://localhost:8090/actuator/prometheus | grep '^credit_'
```

Метрики процесса считаются по истории статусов. Пример: время от отправки до решения и доля автоматических решений.

```sql
-- Медианное время от отправки до решения, в секундах
select percentile_cont(0.5) within group (order by extract(epoch from d.created_at - s.created_at)) as median_seconds
from status_history s
join status_history d on d.application_id = s.application_id
                     and d.to_status in ('OFFER_MADE', 'DECLINED')
where s.to_status = 'SUBMITTED';

-- Доля решений без участия андеррайтера
select avg(case when actor_type = 'SYSTEM' then 1.0 else 0.0 end) as auto_share
from status_history
where to_status in ('OFFER_MADE', 'DECLINED');
```

Подключиться к базе стенда: `docker compose exec db psql -U credit credit`.

## Чего не измеряет прототип

- Поведение в интерфейсе (клики, время на экране, уходы со страницы) не собирается: в прототипе нет системы веб-аналитики, а события помощника пишутся в журнал без текста сообщений.
- Качество кредитного портфеля требует данных обслуживания кредита, которые находятся за рамками кейса.
