# Допущения и упрощения

Здесь собраны все упрощения прототипа и причины, по которым они допустимы. Условия кейса разрешают моки и упрощённую кредитную логику при явном описании.

## Данные

| Допущение | Причина |
|---|---|
| Все данные синтетические: компании, люди, ИНН, оборот, история, документы | требование кейса, реальных данных нет и не используется |
| Профиль компании и финансовый снимок заведены заранее | клиент является действующим клиентом банка, банк уже знает о нём эти данные |
| Регистрации нет, вход по заранее заведённым учётным записям | рассматривается действующий клиент |
| Одна учётная запись на компанию, юридические полномочия сотрудников не моделируются | выходит за рамки MVP |
| Загруженные документы не распознаются, андеррайтер просматривает их вручную | обработка документов — дополнительная функциональность |

## Аутентификация

Вход по логину и паролю, пароли хешируются BCrypt, доступ по JWT с коротким временем жизни. Это простой надёжный вариант для прототипа. В промышленной версии — единая аутентификация банка (см. `PRODUCTION_ROADMAP.md`). Финальное решение по хранению токена на клиенте записать сюда после реализации.

## Моки внешних систем

| Мок | Что имитирует | Правило поведения | Реальная замена |
|---|---|---|---|
| Реестр (аналог ЕГРЮЛ/ЕГРИП) | существование и статус компании, ОКВЭД, дата регистрации | детерминированно по ИНН и профилю компании; одна компания возвращает статус «в процессе ликвидации» | интеграция с официальными реестрами |
| БКИ | история платежей: просрочки, их длительность | детерминированно по профилю компании | запрос в бюро кредитных историй с согласием клиента |
| ФНС | налоговая задолженность | детерминированно по профилю компании | сервисы ФНС |
| Подписание | подтверждение договора и согласий | код из шести цифр, показывается в интерфейсе, три попытки | интеграция с ДБО и сервисом электронной подписи |
| Выдача | зачисление средств | запись о симуляции, без операций | проводки в банковской системе |

Моки скрыты за интерфейсами (`CompanyRegistryClient`, `CreditBureauClient`, `TaxServiceClient`, `SigningProvider`, `DisbursementProvider`), поэтому замена не затрагивает бизнес-логику. Опционально имитируется задержка (`MOCK_LATENCY_MS`).

## Скоринг и кредитная логика

- Скоринг — прозрачный набор правил, без ML. Пороги и баллы — экспертные и приведены в документации продукта; для реального банка они калибруются на исторических данных.
- Скоринг и решение разделены: оценка риска не определяет итог в одиночку.
- Продукты и ставки придуманы, не связаны с реальной линейкой банка. Ставка считается как ключевая ставка плюс спред продукта плюс премия за риск. Ключевая ставка берётся из конфигурации `KEY_RATE_PERCENT`, актуальное значение подставляется перед сдачей.
- Платёж считается по аннуитетной схеме с округлением до рубля.

## Очередь и процесс банка

- Приоритеты и SLA условные: приоритет 1–10, SLA четыре часа (настраивается).
- Список проверок по задаче формируется простыми правилами по параметрам заявки.
- Эскалация, антифрод и многоуровневое согласование не моделируются.

## Подписание и выдача

Подписание и выдача смоделированы без реальных операций. Код подтверждения показывается в интерфейсе, потому что письма, SMS и мессенджеры не должны входить в сценарий.

## Асинхронная обработка

Обработка после отправки идёт в отдельном пуле потоков с небольшой паузой между шагами (`PIPELINE_STEP_DELAY_MS`), чтобы смену статусов можно было наблюдать. В промышленной версии пауза не нужна, а обработка идёт через брокер сообщений.

## Хранение файлов

Документы хранятся в томе Docker, в БД лежат метаданные. Антивирусной проверки и шифрования хранилища нет.

## ИИ

В основном процессе нет LLM и ML. Опциональный блок пояснений (если реализован) использует только модели с открытыми весами через OpenAI-совместимый API, по умолчанию выключен, на критическом пути не участвует. Источник модели указывается в `THIRD_PARTY_NOTICES.md`.

## Прочее

- Интерфейс рассчитан на десктоп, мобильная адаптация — бонус.
- Нагрузочные требования и SLA не заявлялись, прототип рассчитан на демонстрацию.
- Журнал допущений обновляется по ходу разработки: любое новое упрощение добавляется сюда сразу.
