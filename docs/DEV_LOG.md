## Записи

## Этап 0. Каркас — 2026-10-23

Сделано:
- `docker-compose.yml`: сервисы `db` (PostgreSQL 16), `backend` (Spring Boot), `frontend` (nginx со статикой React); у каждого healthcheck, `restart: unless-stopped`, лимиты памяти (суммарно до 1,4 ГБ); тома для данных БД и файлов документов.
- `backend/`: Spring Boot 3.5.6 на Java 21, модули Web и Actuator, `/actuator/health` с пробами readiness и liveness, `GET /api/ping`, тест на оба эндпоинта; многоэтапный Dockerfile, запуск от непривилегированного пользователя, `-Xmx512m`.
- `frontend/`: React 18 + TypeScript + Vite 6, страница-заглушка показывает состояние backend; nginx проксирует `/api`, health, Swagger; `package-lock.json`.
- `.env.example` со всеми параметрами из брифа, заготовки `README.md` и `THIRD_PARTY_NOTICES.md`.

Как проверить:
1. `cp .env.example .env && docker compose up --build`
2. `docker compose ps`: все три сервиса `healthy`.
3. http://localhost:3000 открывает заглушку с надписью «Сервер: работает».
4. http://localhost:3000/actuator/health и http://localhost:8081/actuator/health отвечают `{"status":"UP"}`.
5. `git ls-files | grep .env` показывает только `.env.example`.

Отклонения от плана:
- Этап собран в облачной среде, где закрыты Maven Central и Docker Hub. Фронтенд собран (`npm run build`), `docker compose config` валиден. Сборка backend, тесты и `docker compose up --build` в этой среде не выполнялись и требуют проверки на локальной машине.
- Maven Wrapper не добавлен по той же причине (нет доступа к его дистрибутиву). Docker-сборка его не требует: используется образ Maven. Добавить одной командой на машине с доступом к Maven Central: `cd backend && mvn -N wrapper:wrapper -Dmaven=3.9.11`, затем закоммитить `mvnw`, `mvnw.cmd`, `.mvn/`.
- Подключение к БД появится на этапе 1 вместе с JPA и Flyway; на этапе 0 backend от базы не зависит, но стартует после её готовности.

Коммит / тег: ветка `stage-0-skeleton`

## Этапы 1–5. Backend: данные, заявка, конвейер, банк, сделка — 2026-10-23

Сделано:
- Миграция `V1__schema.sql`: все таблицы из раздела 5 брифа, проверки допустимых значений статусов, оптимистическая блокировка заявки и задачи, частичный уникальный индекс «не больше одной задачи в работе у андеррайтера». Демо-данные `V100__demo_data.sql` (профиль `demo`): 3 продукта, 9 компаний, 9 учёток, 3 исторические заявки (выданный кредит и две задачи в очереди), 12 новостей и подсказок с таргетингом.
- Доступ: вход по логину и паролю (BCrypt), JWT HS256, роли `CLIENT`/`UNDERWRITER`, разделение эндпоинтов по ролям, принадлежность заявки проверяется в сервисе (чужая заявка даёт 404), ошибки в формате problem+json с кодом и идентификатором корреляции.
- Заявка: каталог и подбор продукта с объяснением, черновик с проверкой границ продукта, документы с ограничениями по типу и размеру, отправка с согласиями (202), проверка полноты с автоматическим запросом данных, машина состояний и история.
- Конвейер: асинхронная обработка с паузой между шагами, моки реестра, БКИ и ФНС за интерфейсами с имитацией задержки и сбоя, скоринг по разделу 7, кредитная логика (отказ, ручная проверка, автоодобрение, встречное предложение), цена, пояснения. Дообработка незавершённых заявок после перезапуска.
- Банк: очередь с приоритетами и SLA, «взять следующую» через `SELECT … FOR UPDATE SKIP LOCKED`, проверки по правилам раздела 8, пересчёт скоринга с историей запусков, решения с правилами завершения, запрос данных и возврат задачи тому же андеррайтеру с приоритетом 1.
- Сделка: принятие или отклонение предложения, подписание шестизначным кодом (хранится только хеш, три попытки), симуляция выдачи, журнал аудита, лента «Для вас» с событиями и подсказками, подобранными по сегменту, отрасли, продукту и статусу.
- Сброс демо-данных `POST /api/dev/reset-demo` (только профиль `demo`).

Как проверить:
1. `cp .env.example .env && docker compose up --build`.
2. Чек-листы этапов 1–5 из инструкции команды; сценарии S1–S7 из `docs/TEST_SCENARIOS.md` через Swagger или Postman.
3. `cd backend && mvn test` (юнит-тесты и интеграционные тесты сценариев, нужен Docker для Testcontainers).

Что проверено в среде разработки:
- SQL миграции и сида выполнен на PostgreSQL 16 без ошибок.
- Доменная логика (скоринг, цена, кредитная логика, подбор продукта, правила очереди, машина состояний) скомпилирована JDK 21 и прогнана: 26 юнит-тестов зелёные, сценарии S1–S7 дают ожидаемые грейды и исходы (S1 и S7 — автоодобрение, S2 — встречное на 840 000 ₽, S3 и S4 — ручная проверка с приоритетами 2 и 5, S5 — грейд D, S6 — жёсткий стоп).
- Весь backend скомпилирован против заглушек API Spring, JPA и Jackson: ошибок нет, но это проверяет только согласованность собственного кода, а не реальные сигнатуры библиотек.

Отклонения от плана:
- Maven Central и Docker Hub в среде разработки закрыты, поэтому полная сборка, запуск Spring-контекста и интеграционные тесты не выполнялись. Первый `docker compose up --build` и `mvn test` нужно прогнать на локальной машине; возможные ошибки конфигурации Spring проявятся именно там.
- Lombok не используется: аксессоры сущностей написаны явно, меньше зависимостей и обработчиков аннотаций.
- Таргетинг новостей хранится в колонках, а не в JSONB (обоснование в `ASSUMPTIONS.md`).
- Интеграционные тесты названы `*IntegrationTest`, чтобы их запускал `mvn test` без отдельного плагина.

Коммит / тег: `7718ab2`, ветка `stage-0-skeleton`

## Этапы 6–7. Интерфейсы клиента и банка — 2026-10-23

Сделано:
- Клиент: вход с подсказкой демо-учёток, главная (карточка компании, заявки, лента «Для вас» с объяснением показа), подбор продукта, мастер заявки из четырёх шагов с автосохранением черновика, страница заявки (статус-трекер, «Что дальше», ответ на запрос с загрузкой документа, карточка предложения с переплатой и блоком «Почему такие условия», подписание кодом, результат выдачи, «Почему так» с таблицей факторов, история, документы). Подсказки к терминам. Состояния загрузки, пустого списка и ошибки.
- Банк: очередь с фильтрами, приоритетом, SLA и подсветкой просрочки, «Взять следующую задачу», карточка с вкладками (сводка, компания и финансы, документы с пометкой «новое», скоринг с историей запусков, проверки, история), панель пересчёта и решения с подсказкой, какие решения доступны и почему.
- Статусы обновляются опросом (заявка каждые 3 с, очередь каждые 3 с), действия андеррайтера видны клиенту без перезагрузки.

Как проверить: сценарии S1–S7 из браузера по `README.md`.

Что проверено в среде разработки: `tsc` без ошибок, `npm run build` проходит, 10 тестов Vitest зелёные (статус-трекер, проверка условий заявки, карточка предложения). Интерфейс против работающего backend не открывался.

Отклонения от плана: адаптивная вёрстка сделана базово (одна колонка на узких экранах).

Коммит / тег: `c8c0b39`, ветка `stage-0-skeleton`
